Test preparation

Start here

Set up a safe test journey

Follow one disposable memorial from Draft to Private Preview to Published, then back to Draft. Keep real memorials untouched.

What testers need

  • Desktop browser and a phone.
  • Admin credentials supplied privately.
  • Male, Female and Child sample memorials.
  • One long and one short Life Story.
  • Sample photo, video and optional stream URL.
  • Access to approved family and partner inboxes.

Release readiness

  • Latest Vercel frontend is Ready.
  • Latest Render API is Live.
  • /api/health responds successfully.
  • Render reports PostgreSQL connected.
  • Brevo and Cloudinary are configured.
  • PUBLIC_SITE_URL matches the intended website origin.

Run local automated checks

npm run lint --workspace apps/web
npm run build --workspace apps/web
npm run test --workspace apps/api
npm run build --workspace apps/api
npm run prisma:validate --workspace apps/api

Run from repository root. Do not alter production data or run a migration solely for this test.

Memorial directory - /memorials

  1. Open from homepage; cards begin loading without an unnecessary delay.
  2. Search by name; results filter without a request on each keystroke.

  4. Network should show /api/memorials?summary=1; it omits Life Stories and full galleries while retaining card counts.

Priority acceptance

Share with confidence

Public link, sharing and QR

Release-critical: Copied URL, public Share action and scanned QR must resolve to the same canonical memorial. Draft, Private Preview and Archived records must not expose the public page.

Admin-to-phone test

  1. Sign in at /admin/login. In /admin/memorials, find labelled Share / QR in the sample row.
  2. Open its saved editor; find the same Share / QR control. A new unsaved memorial has no link yet.
  3. Open modal: verify person's name, slug, status, QR preview and full public URL.
  4. Copy and paste the link. Format: https://palm-grace-web.vercel.app/memorial/{slug} or approved custom domain.
  5. Download SVG and PNG; open both to ensure they contain a readable QR, not a 401/error document. Check print preview.
  6. Publish and save the sample. Open copied URL in a private window; scan QR with a phone. Both open the same person.
  7. Use the public page's Share control and confirm it points to that same URL.
  8. Unpublish to Draft. Old URL and QR must no longer expose memorial content.

Pass: published

Copy works; public page opens; phone scan matches; SVG, PNG and print are usable; public Share points to the canonical link.

Pass: private

Admin can prepare draft/preview QR, but public page remains inaccessible until publication. Archived stays unavailable.

If this fails

Check Render PUBLIC_SITE_URL, saved publication status, admin session, Vercel /api/* proxy and Network response from /api/admin/memorials/{id}/qr. Do not distribute a QR until a real phone scan succeeds.

Protected workflows

Admin, media, tributes and forms

Authentication and editor

  • Signed-out /admin redirects to login; wrong password is rejected; correct login works; logout protects admin pages.
  • Dashboard counts/navigation work; password eye icon and mobile admin layout are usable.
  • On disposable sample, save preferred name, dates/show-hide, line, Life Story, service/wake, stream/recording, acknowledgement, closing words and template.
  • Preview privately, then test Draft, Private Preview, Published and Archived; verify public visibility after each save.
  • Upload photo/video via Cloudinary, reorder gallery, remove only a sample file and confirm public order.

Tribute moderation

  1. Submit a unique sample memory on a published memorial; success says pending review.
  2. Before approval, memory is not public. Admin sees it under Pending Review.
  3. Approve and refresh public page; memory appears. Decline another test memory; it remains hidden.
  4. Contributor email, if provided, stays private to admin and never appears in public API/page.

Two separate enquiries

Begin a Memorial

Validate required fields and invalid email; send one clearly labelled TEST enquiry. Gentle success message appears and the configured family inbox receives the branded email.

Care Partner

Check organisation, contact, role, location and enquiry fields. Send one TEST enquiry; the configured partner inbox receives it separately.

If a form returns 503: inspect Render destination-email variables, Brevo API key/verified sender and delivery logs. An error must not be shown as success. Avoid rate-limit testing on the live client inbox.
